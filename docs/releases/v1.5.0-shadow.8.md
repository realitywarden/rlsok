# v1.5.0-shadow.8 — observed Nav2 goals and Hexapod simulation configuration

The earlier Nav2 JSON comparison did not fulfill the requested running-graph and before-dispatch negative cases. This release adds [read-only Nav2 observation and the final exact-goal Shadow check](../nav2-observed-shadow.md). It also completes the [public Hexapod simulation workflow](../hexapod-observed-shadow.md) with fresh gait parameters, its selected trajectory output link and the active downstream 18-joint controller state.

Nav2 local approval binds the observed selected configuration, endpoint/interface metadata and an exact FollowPath goal. Each Shadow check obtains a new two-pass ROS observation and gives its local sink only a detached, deeply frozen matching goal. Changed selectors/path, changed semantics, ambiguous topology, stale/failed captures and invalid approvals block before that sink. The CLI has no robot action transport; its only allowed handoff writes a local evidence file.

Hexapod source workspaces now require `--controller-state` and `--node-settings` on prepare/refresh. Their original export timestamps participate in the existing freshness checks. The gait input receiver must match the parameter-export source; the separate downstream controller must match the pinned 18-joint mapping. Existing older Hexapod workspaces need a new explicit review to include these facts; approvals are never silently upgraded.

Targeted verification performed:

- Seven Nav2 gate test groups: exact selectors/path, detached immutable goals, concurrent mutation, modified/expired approvals, freshness/replay/capture failures, bounded timeout and accurate sink-failure reporting.
- Six source-workspace groups covering the changed shared preparer/refresh path, including missing/stale/wrong gait sources, downstream links and changed gait facts under the old approval. Two Python node-export tests cover discovery lag, conflicting publishers and mid-read changes.
- [23 real Jazzy/Nav2 graph cases](../validation/feedback-20260910/nav2/summary.json) using Nav2 1.3.12, actual controller/smoother/collision-monitor processes and an explicitly labeled software base. Same-limit semantics, all three per-goal selectors, path substitution, extra publishers/bypass subscriptions, inactive smoother, collision configuration and CLOSED_LOOP source/frame/duration changes block. Volatile-only velocity changes match. Recreated endpoints require explicit new review.
- [12 Gazebo path cases](../validation/feedback-20260910/nav2-gazebo/summary.json) use the actual ROS-GZ bridge and Gazebo 8.14.0 DiffDrive model. The prerequisite observed 2,096 Gazebo odometry messages through the bridge; [Gazebo topic metadata](../validation/feedback-20260910/nav2-gazebo/gazebo-command-topic.log) shows both publisher and simulator subscriber. RLSOK sent zero actions/velocity commands and zero velocity messages reached the selected input before shutdown.
- [The public Hexapod Gazebo comparison](../validation/feedback-20260910/hexapod/summary.json) builds only its two Python ROS packages at `656eebab`. The original model, gait/IK and real controllers run in neutral stance: 1,893 trajectory messages, 4,246 joint-state messages and 10,172 clock messages were observed before shutdown, with no `/cmd_vel` message. Restarting only the gait with `cycle_time` 1.0 → 2.0 changes `WOULD_ALLOW` to `WOULD_BLOCK`; the 18-joint controller configuration and original profile/approval/candidate remain unchanged. The nonzero candidate is local data and is never published.
- TypeScript delivery build and focused diff review. Clean-source packaging rebuilds the deliverable without invoking tests.

The experiments uncovered and corrected real integration issues: unsupported YAML aliases in the fixture, a known intentionally uninitialized deprecated Nav2 polygon parameter, the actual rclpy QoS return shape, initial discovery lag, and loopback multicast setup for isolated Gazebo transport. Failed/aborted attempts were retained locally and are not counted as passes. The public Hexapod source emits a duplicate-shutdown diagnostic when its gait process is terminated; its source was left unmodified, and this teardown diagnostic is not represented as a RLSOK runtime failure or a locomotion result.

No full suite, GitHub Actions, physical robot dispatch, fresh Humble validation or customer acceptance test was run. Installed ROS package metadata and graph observations do not authenticate physical hardware or adversarial DDS participants. OPEN_LOOP remains a command-space claim. This is a zero-dispatch evaluation prerelease; stable v1.4.5 remains separate.
