# v1.5.0-shadow.11 — confirmed Piper roles and paired Sunrise review

Evaluation prerelease. Customer integration, hardware use and acceptance remain
separate from this software delivery.

## Changes

- [Piper confirmed-role input](../piper-confirmed-roles.md) accepts the saved
  single/bimanual, side, joint/delivery and camera/CAN mapping without requiring
  an invented native launch file. It preserves robot serials and stable adapter
  identities, emits an explicitly operator-supplied inventory, and uses the
  existing immutable baseline/difference workflow. It does not wire start_gui.sh
  or pretend the inventory is a fresh device scan.
- [KUKA ROS/Sunrise preparation](../kuka-sunrise-saved-review.md) pairs the
  public Java application, C++ bridge, dual launch and build files, with optional
  selected local overrides. Message/telemetry logs are unnecessary for this
  saved-file phase; no UDP or cabinet connection is created.
- Linux USB discovery stops at the endpoint's own USB device. A missing unit
  serial can no longer be replaced by an upstream hub's serial.
- Saved files reject invalid UTF-8 instead of normalizing invalid bytes to
  replacement characters before semantic comparison.

## Actual evidence

The TypeScript build completed. Using one privately supplied, operator-confirmed
Piper mapping, twelve bounded offline comparisons produced the intended reports:
unchanged; camera missing; CAN missing; ambiguous camera; renumbering; consistent
role exchange; wrong CAN locators; delivery mode; single left; single right;
changed robot serial; changed camera model. Renumbering used deliberately
constructed saved inventory and resolved copies. No fresh device scan or
physical replug was performed. Private identifiers and reports are not published.

A saved copy of the pinned public KUKA Java port declaration was changed from
30300 to 30301. The actual comparison reported REVIEW_REQUIRED at
/files/sunrise under the unchanged preparation baseline. This was a deliberately
changed offline example, not a deployed configuration or protocol validation.

Changed Python modules were syntax-parsed and source/diff-reviewed. Full tests,
GitHub Actions, ROS, real device discovery, camera capture, SDK/CAN/UDP operations,
customer GUI integration and installed Linux bundle trials were not run. No
hardware was controlled. Build/package integrity does not establish those results.

MakerModsLab's optional native-record capture/comparison wrapper is delivered in
a separate draft PR. Maintainer review/merge, their actual selected record and
calibration comparison, and bench use remain pending. No customer is marked
fully integrated on the strength of this release or a sent email.
