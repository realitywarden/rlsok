# RLSOK Local Check 1.5.8

This release completes one missing part of the Piper role-mapping input found
in an owner-run real-workstation check. It does not claim GUI integration,
repeat use or customer acceptance.

## Piper camera identity fallback

- `profile prepare-piper-setup` continues to prefer the camera's unique serial.
- When the camera genuinely exposes no readable unit serial, an operator may
  explicitly select an already-reviewed `usb_path` together with the stream's
  `interface` and `videoIndex`.
- The input requires exactly one identity basis. It never silently falls back
  from a missing serial to USB topology, model name or `/dev/videoN` order.
- Missing or ambiguous USB-path observations refuse resolution. Changing the
  path or changing between serial and USB-path identity requires review against
  the preserved baseline.
- Generated warnings state that USB topology identifies a port, not a unique
  physical camera. Replacing the unit at the same port still needs manual review.

See the [Piper role guide](../piper-confirmed-roles.md). The prepared
`operator-inventory.json` remains a selected-role import, not fresh hardware
evidence. A real workstation comparison needs a separately captured read-only
inventory.

## Focused verification and limits

Thirteen synthetic Piper tests passed. They cover mixed serial/USB-path roles,
the old serial-only shape, strict identity selection, required stream fields,
duplicate identities/endpoints, single-arm role completeness, explicit endpoint
renumbering, missing/ambiguous refusal, identity-basis changes and unchanged
review. The existing profile tests also passed, and TypeScript compilation is
performed by each focused test entry.

No full suite or general GitHub Actions run was performed. No customer archive
or device identifier is included. No CAN, camera, robot SDK, policy, GUI or
motion process was opened. This release does not establish that the customer's
project-side resolver or `start_gui.sh` integration is complete, nor that RLSOK
has been used repeatedly in normal robot sessions.
