# v1.5.0-shadow.3 — local velocity-topic evaluation and readable comparisons

This evaluation prerelease lets an operator select a standard ROS 2 Twist or TwistStamped topic and its intended receiving node, evaluate a local message example, and compare two observations against the same approved setup. It sends zero controller commands. Existing action adapters remain available.

- Discovery records installed message-definition fingerprints and actual subscriber metadata. The selected subscription must be unambiguous; a logger is never selected automatically. Standard vectors, frame conventions and stamped-message structure are checked.
- `profile shadow` now writes a human-readable `report.md` alongside the existing JSON assessments, policy descriptions and chained Evidence.
- `profile compare` keeps the profile, approval and proposals fixed, writes both complete reports and identifies changed check outcomes. Stale/missing inputs are distinguished from the intended configuration change.
- The first-evaluation guide explains required inputs, repository/access needs, offline operation, isolated simulation, local approval versus physical safety, recorded information and private/public collaboration boundaries.
- The browser configuration workflow shares the portable Runtime validators and exports a workspace for the local CLI. Website deployment is a separate delivery stage.

Read [the first-evaluation guide](../local-shadow-first-evaluation.md), [configuration guide](../interface-onboarding.md) and [installation guide](../fanuc-shadow-self-service.md). Download START-HERE.md and INSTALLATION.md with the release, or use the complete linked guides inside the package/source archive.

## Validation scope

Targeted local checks on Windows, 2026-09-08:

- Seven tests in `tests/composable-shadow/topic.test.ts` passed: Twist/TwistStamped round trips and Evidence consistency; same-approval controller change; missing/duplicated/replaced receiver; explicit mapping and semantics rejection; catalog tampering; invalid/stale inputs; and the four existing action-adapter decisions.
- Five mock-ROS collector tests in `experimental/composable-shadow/test_topic.py` passed: recursive message fingerprints, duplicate subscriptions, conflicting graph metadata, actual local file bytes and absent receiver, and no command publisher/client/subscription API usage.
- Runtime TypeScript delivery build completed. The packaging command builds and packages without invoking tests or Actions; manifests refer to this explicit validation record.

No full test suite, full gate, GitHub Actions, actual ROS/Jazzy/Humble/Gazebo run, Linux installer execution, private customer integration or physical robot validation was performed for this prerelease. Synthetic checks do not establish those outcomes. Website browser-to-CLI verification and deployment are recorded in the website delivery evidence separately.

Local file hashes do not prove a controller loaded the file. Graph metadata does not establish hardware identity, QoS delivery, readiness or complete command-path coverage. The supplied example message is evaluated from a file; live commands are not intercepted or forwarded. Existing robot safeguards are required. A WOULD_ALLOW decision is a local configuration result, not a motion-safety claim or production execution permit.

Stable Runtime v1.4.5 and Cloud/API/schema remain separate. Install into a new evaluation directory; do not replace a running robot execution stack. Publication establishes availability, not customer trial use or acceptance.
