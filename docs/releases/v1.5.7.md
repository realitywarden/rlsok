# RLSOK Local Check 1.5.7

Two opt-in tools turn specific feedback into reusable checks, while preserving
the existing Windows, native Mac and Linux first-run examples.

## Included additions

- `profile compare-create3-versions` compares two operator-saved Create 3
  version reports. Only explicit reported fields are selected; missing,
  unavailable or duplicated material cannot silently count as a match. The
  private engineering example is not included. No SSH or robot connection is made.
- `profile capture-mowgli-status` subscribes to an already-running MowgliNext
  status topic. It checks the unique expected publisher and full per-message
  GID, rejects the public fake bridge and `sim` firmware, and separates an
  incomplete handshake from a usable observation. It never starts the bridge,
  opens USB/CAN, calls parameter services or sends a robot command.
- `profile compare-mowgli-status` compares saved reported firmware plus an
  optional explicit wheel/PID setting selection. This comparison is offline;
  the selected saved settings are not represented as live/applied values.

See the [Create 3 guide](../create3-saved-version-review.md) and
[Mowgli guide](../mowgli-readonly-status.md) for inputs, commands and limits.
The Mowgli capture requires the owner's existing ROS 2/message environment,
Git and Python; the desktop package alone does not supply a robot connection.

## Verification and limits

The ten focused Create 3 tests and twelve synthetic Mowgli tests passed; the
TypeScript build also succeeded. These checks cover parsing, metadata rules,
saved comparison and refusal cases. No full test suite was run. Packaging and
platform installation records accompany the respective platform releases.

No physical Create 3 or mower trial, live Kilted/DDS interoperability,
authenticated device identity, firmware-applied PID verification, safe motion
authorization or customer acceptance is claimed. ROS discovery and node
bookkeeping still produce network traffic during the opt-in observer.

Use a new installation directory and keep existing approved references. This
release does not migrate the separate stable robot-runtime or desktop update
feeds. Previous releases, checksums and emailed links remain unchanged.
