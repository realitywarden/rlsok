# v1.5.0-shadow.12 — selected-input checks and readable configuration differences

This evaluation prerelease completes further source-based work from the
reviewed email feedback. It does not replace the stable runtime or authorize
robot movement.

- Saved-setup reports show before/after field values and changed source-line
  excerpts. Missing/invalid selected files and missing mapped fields produce
  `NEEDS_MATERIAL`; ambiguous device aliases cannot become an unchanged match.
- SO101 inspection connects the selected motor map, calibration, controller
  interfaces, model joint declarations and hardware/bridge topics. It reports
  the reviewed public position/velocity mismatch without choosing a customer's
  controller or measured calibration.
- Beast inspection records declared bridge parameters and duplicate YAML
  errors, and distinguishes `watchdog_timeout` from `cmd_vel_timeout`.
- Cartesian single/dual inspection maps source endpoints, ordered joints and
  frames. Optional saved PoseStamped/WrenchStamped/JointMove checks cover
  endpoint/role, coordinates, quaternion, array order/count and duration. They
  are offline checks, not a runtime ROS hook. The reviewed wrench receiver
  ignores the header frame and uses `hand_frame_control` instead.
- The Metal recipe supports Star, vertical Star and Metal leaders and records
  selected source files. An omitted/empty leader kind follows the known Star
  application default while preserving the original record.

The separate MakerMods contribution adds native record selection summaries,
the vertical-Star calibration library and a direct Node/CLI option for the
stdlib review wrapper. It remains an optional draft PR, not an upstream merge
or a customer bench trial.

See [selected-input inspection](../selected-input-inspection.md),
[saved-setup review](../saved-setup-review.md),
[Piper confirmed roles](../piper-confirmed-roles.md), and
[paired KUKA/Sunrise review](../kuka-sunrise-saved-review.md).

Validation was limited to the necessary TypeScript build, Python syntax,
source/diff review, bounded offline source/synthetic workflows and manual
release asset verification. No full suite, GitHub Actions, ROS launch,
hardware scan, CAN/serial/UDP connection or robot motion was executed.
Actual private selections remain operator inputs; source examples and sending
materials are not customer integration or acceptance.
