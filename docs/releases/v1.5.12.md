# RLSOK Local Check 1.5.12

## What changed

- The existing local, account-free setup assistant now accepts an expanded URDF and selected JSON/YAML project files. It suggests a model, movable joints, controller names and joint orders, and shows remaining inputs before export.
- A user can start from one discovered standard Twist or FollowJointTrajectory interface, or explicitly choose a documented custom action meaning. Versioned fragments can be combined with that starter and saved for reuse.
- A separate cross-machine template export retains common field mappings and checks while leaving endpoint, receiver, frame, robot identity and selected files as per-machine inputs. The existing same-machine private template remains available.
- Installed ROS field definitions offer pointer suggestions. An actual goal or message, intended receiver, units, frames, bounds and physical meaning still require explicit review and confirmation.
- Export includes a validated connection, profile, proposals, catalog, exact selected source files, a private reusable template and instructions for the next read-only checks. Existing adapters, saved-file recipes, observers and release channels remain intact.

## Important limits

Structural inspection does not establish units, physical meaning, the active controller configuration or hardware compatibility. Xacro is not expanded. ZIP generation is not approval, fresh observation, motion permission, customer trial or acceptance. The assistant sends no robot command and does not use AI or a cloud upload.

## Focused verification

TypeScript type checking and build passed. Focused tests covered project inspection, standard-interface starter matching, explicit semantic confirmation, validated connection creation and ZIP output. The local HTTP page was fetched and its browser script parsed on Windows. The full suite and physical-robot checks were not run.
