# RLSOK Local Check 1.5.1

Compare selected Modular DiffBot and Piper CPP files, and map absolute
Cartesian XYZ/native W/P/R inputs without changing their units or meaning.

## Changes

- New `cartesian_absolute_wpr` adapter: absolute XYZ in mm, native FANUC W/P/R
  in degrees, exact frame label, uint16 velocity and explicit reviewed
  default/maximum. Velocity zero uses the configured default; zero pose is
  never treated as a no-op. CLI schemas and interface onboarding share these
  rules. Existing quaternion and relative-jog adapters remain distinct.
- Modular DiffBot saved-file recipe: selected bridge parameters, teleop and
  remapping record, bridge/firmware/launch/model copies and package source.
  Reports retain source changes and the original baseline. Bridge PWM and
  firmware limiting remain separate settings; no network connection occurs.
- Piper CPP saved-file recipe: explicit arm/gripper/CAN/activation selection,
  controller/model files, optional MoveIt settings, and SDK/control source.
  This is separate from the existing bimanual Piper recipe. No CAN, SDK,
  controller, home/enable operation or model generator is started.
- Selection helper, examples and complete guides; numbered release and
  version-bound installers preserve previous emailed release assets.

## Verification and limits

Thirteen focused offline absolute-WPR cases passed: native input preservation,
velocity/default/bounds and frame validation, missing/nonfinite inputs,
duplicate pointers, original-approval calibration change and consistent
zero-dispatch Evidence. Twelve targeted saved-workflow checks used the pinned
public DiffBot and Piper CPP sources, source-derived selections and a synthetic
Piper model: unchanged/change/missing/invalid inputs and retained baseline.
Nine additional private source-mapping checks used supplied action definitions
and redacted examples with explicitly synthetic catalog/environment/state;
private material is not included in the release.

TypeScript build and necessary package assembly were performed. No full test
suite, GitHub Actions, robot process, physical connection or command was run.
The Linux bundle was assembled on Windows; this does not establish Linux
installation or ROS 2 Humble compatibility. Source mappings do not establish
installed interface identity, active controller tool/frame, live driver
defaults/allowlist, deployed firmware, calibration accuracy, real use or
customer acceptance. Those require the actual selected inputs and evidence.

The file comparator does not prove selected settings are active or mechanically
valid. No physical safety or continuous authorization control is added.
The separate stable robot-runtime and Windows management-app feeds retain
their existing scope and versions. Historical downloads/checksums stay intact.
