# v1.5.0-shadow.9 — passive Tello configuration review

The earlier Tello demo recorded requests but did not compare selected
configuration or produce Shadow decisions. This release connects the patched
public client to local baseline capture, explicit approval, fresh configuration
comparison and private JSON/Markdown evidence. Start with the
[complete Tello guide](../tello-passive-shadow.md).

The optional record is copied after the owner's original `call_async`. A
separate process observes ROS node/service associations, the installed
TelloAction definition, ROS environment and selected files. Changed, ambiguous,
missing, stale or inconsistent evidence cannot establish a match. `WOULD_ALLOW`
and `WOULD_BLOCK` are post-call configuration reports: RLSOK sends, blocks,
cancels and retries zero robot commands. This dedicated review does not issue a
core Permit or claim command safety, physical identity or atomic dispatch state.

The CLI now provides `capture-tello`, `approve-tello`, `watch-tello` and
`review-tello`. Without an approval the watcher only captures facts. It never
silently approves or refreshes a baseline. The bundle includes the helpers,
patch, selection template and guide; its versioned installer now selects this
release. Existing prerelease assets and earlier email links remain available.

Focused verification performed:

- Four TypeScript test groups covering exact request recording, configuration
  changes, endpoint/type/client/server changes, missing/stale/ambiguous/lost
  input, modified/expired approvals and actor normalization.
- Eight Linux passive-recorder checks, including real local datagrams and a
  separate recorder process, disabled/absent/broken/full receivers and the
  original client's call/future/spin ordering under recording errors.
- [Seven real Jazzy service scenarios](../validation/feedback-20260911/tello/validation.json)
  using the pinned public client class and an actually built TelloAction
  serializer against a unique localhost mock service: matching baseline,
  selected-file change under the same approval, restoration, two real servers,
  recorder stopped, capture without approval with a missing session prefix,
  and recorder started before a fresh client followed by explicit approval of
  its captured baseline. All seven owner calls completed. Eight mock-server
  receipts occurred because two same-name servers can receive one request;
  owner calls and server receipts are counted separately. RLSOK and physical
  command counts are zero. The public automatic takeoff/stop `main()` and Tello
  driver were never run.
- TypeScript compilation and focused source/diff review. Release packaging
  rebuilds from the clean committed source without invoking tests.

The service experiment exposed and corrected fixed-delay discovery assumptions
and a stop-time report/summary accounting race. Failed attempts and the initial
cross-filesystem CLI startup timeout were retained privately and not counted as
passing results. The final observation waits for selected metadata with a bound,
then takes a fresh two-pass snapshot; it never waits in the owner's command path.

No full suite, GitHub Actions, fresh Foxy/Humble validation or physical-drone
acceptance test was run. Current customer launch/remaps, local changes and
hardware results remain unconfirmed. This is a local evaluation prerelease;
stable v1.4.5 remains separate.
